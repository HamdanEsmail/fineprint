# Fineprint build log

What changed from the plan (`docs/plans/2026-11-03-fineprint-recorder.md`) while building it, why, and every live TinyFish call made during the build with its cost.

## Order of work

- 3 Nov: deploy was cleared early and the order changed: Tasks 1 to 8, then the deploy parts of Task 12 (`pages.json`, `scripts/register-pages.mjs`, `docs/runbook.md`), then deploy, webhook rehearsal and registration of 20 pages, then Tasks 9, 10, 11 and the rest of Task 12, redeploying after each.
- Commits go to `main` and are pushed after each task.

## Choices where the plan left room

- Test bindings are fixed test values (`TINYFISH_API_KEY=test-tinyfish-key`, `ADMIN_TOKEN=test-admin`, `WEBHOOK_SECRET=test-secret`, `PUBLIC_BASE_URL=https://fineprint.test`), and a test asserts the real key never reaches unit tests.
- Tests that depend on `waitUntil` work call the Worker in-process through `tests/helpers/app.ts`, which awaits the execution context before asserting.
- `fetchMock` interception was checked with a throwaway route (removed again): a fetch made inside a request handler is intercepted when the handler is called through `callWorker` (yes) and through `SELF.fetch` (yes), both for a fetch awaited in the handler and one scheduled with `waitUntil`; an unmatched fetch inside a handler throws, Hono answers 500, and the call is recorded. `callWorker` is still the one to use when a test asserts on `waitUntil` side effects, because `SELF.fetch` does not wait for them.
- Test storage (D1 and R2) is isolated per test file, not per test. Tests that need a clean database run `await reset(); await applyD1Migrations(env.DB, env.TEST_MIGRATIONS);` (from `cloudflare:test`) in `beforeEach`; this was checked to clear both D1 rows and R2 objects.
- Typecheck runs on TypeScript 7.0.2 (the native port) with no pin to 6.x needed; it resolves the Workers and plugin types. One `tsconfig.json` covers `src`, `tests` and `vitest.config.ts`. `tests/env.d.ts` augments `Cloudflare.Env` with `TEST_MIGRATIONS`, so that binding exists only in the test environment and not in `src/env.ts`.
- Tests import `env` from `cloudflare:workers` and `SELF` plus the execution-context helpers from `cloudflare:test`. The plugin marks `env` and `SELF` in `cloudflare:test` as deprecated in favour of `cloudflare:workers` (`env`, `exports.default.fetch()`); `SELF` is kept because the plan uses it.
- `callWorker` accepts a bare path such as `/api/stats` and resolves it against `https://fineprint.test`.
- The CI workflow `.github/workflows/check.yml` (push and pull_request, Node 24, `npm ci`, `npm run check`) is created in Task 1; Task 12 only verifies it.
- Beyond the smoke test, Task 1 adds `tests/fetch-mock.test.ts` (the helper's own tests) and `tests/spend.test.ts` (prices and `recordSpend`). The smoke test also asserts the four fixed test bindings, so a real key from `.dev.vars` can never leak into tests; the assertion was checked to fail without the explicit binding.
- npm 11 prints an `allow-scripts` warning for the `esbuild` and `workerd` postinstall scripts. They are not needed (the platform binaries come from optional dependencies) and tests, typecheck and `wrangler deploy --dry-run` all work, so no `allowScripts` entry was added.
- Noise rules (spec 4.3 scope rule): metadata markers (`last updated`, `updated on`, `updated:`, `published`, `effective date`, `page generated`, `as of`) drop a line only when what follows the marker is a date or time stamp, so "As of 1 December 2026 the checked bag fee is $35" is kept. Relative-time lines are dropped only when the whole line is a stamp: an optional verb (posted, updated, edited, published, modified, last updated, last edited, last modified), "N seconds/minutes/hours/days ago", and an optional "by <name>" of at most 40 characters; so "Posted 3 hours ago by admin" goes and "Orders placed more than 30 days ago cannot be returned or refunded." stays. Copyright lines are dropped only when a year (19xx or 20xx) comes right after the marker ("©", "(c)" or "copyright", optionally two of them as in "Copyright (c) 2026") and the line is at most 200 characters, so "Copyright © 2026 Vercel Inc. All rights reserved." goes while "Copyright and trademark complaints: send notices to legal@x.com", "© Vercel" and "(c) From 1 January 2027 the fee rises to $60." stay. Cookie banner phrases ("we use cookies", "accept all cookies", "cookie settings") drop the line only when it is at most 300 characters, so a privacy-policy paragraph that says "we use cookies" stays; the length caps exist because many watched pages are privacy and terms policies. Share counters are a whole line of a number followed by "share(s)"; viewer counters are a whole line of "N people (are) viewing" with at most a few trailing words such as "this page", so "Pro: up to 5 people viewing a board at once" stays. Every rule has a suppressed fixture and a near-miss fixture.
- Spend ledger (spec 4.9 "every TinyFish call appends a spend row"): Fetch and Search calls write $0 rows; Monitor creation writes one `monitor_check` $0.005 row for the baseline check; screenshot session creation writes $0.002; Agent steps are written when a run finishes. Monitor update, pause, delete and list write nothing.
- The CDP WebSocket upgrade to TinyBrowser's `cdp_url` is a plain `fetch` outside `client.ts` (no API key, 101 response). The session-creation POST goes through `client.ts`.
- The change gate normalizes both the incoming text and the latest version's stored text with the page's current ignore patterns (spec 4.3), so editing ignore patterns never creates a false version.
- A `changed` run with fetch errors or empty text is stored with `noise_reason "fetch_error"` but is not counted as suppressed noise.
- `captureVersion` checks the spend pause first (no attempt used), skips captures already done, and never starts a second Agent run for a version that already has one.
- The repair cron only retries versions in `pending` or `partial`; versions in `awaiting_facts` are handled only by the facts follow-up.
- Public URLs: `/shots/<version id>.jpg` reads R2 `shots/<version id>.jpg`; `/sources/<version id>.html` reads R2 `html/<version id>.html`.
- Diff with `from` later than `to` returns 400 `invalid_range`.
- Discover's 10 per IP per day limit applies to public callers only.
- Replay walks only `changed` runs that have a raw payload, in `received_at` order from the baseline; versions it creates are `pending` with `capture_error "replayed"`, and their runs are un-marked as noise.
- Normalization details: a metadata line is dropped when what follows the marker is made only of date and time parts (month names, years, numeric and ISO dates, clock times, weekdays, time zones, "on/at/of/the", "today"/"yesterday") with at least one real date or time part, optionally followed by "by" and up to four name words. A bare day number or a URL is not a stamp. Numeric dates must have a real date shape (`d/m/yy`, `dd.mm.yyyy`, `yyyy-mm-dd`), so "Updated: 1.2.3", "Last updated: 10.5.2" and "Updated: 1299.99" stay. The marker is the word "updated" (so "Updated 2026-11-03", "Updated: 2026-11-03" and "Updated on 2026-11-03" all go); the stamp requirement is what keeps "Updated: Pro now includes 10 seats".
- Normalization details: "copyright" must be a whole word at line start (so "Copyrighted material..." stays); the caps (200 characters for copyright, 300 for cookie banner phrases) are measured on the trimmed line with whitespace collapsed, and "skip to content" has no cap. Relative time uses the plan's units (`seconds?|minutes?|hours?|days?`, digits required), so "an hour ago" and "3 weeks ago" are not caught. Markdown markers (`# * _ > - + | ~` and backticks) are ignored in front of a line and around the counters, the copyright marker and a relative-time stamp. The per-line whitespace collapse is skipped for lines that have no tab, no other non-space whitespace and no double space (the free-plan CPU budget); the speed test allows 100 ms for ~100 KB.
- Normalization details: tracking parameter names match case-insensitively and exactly (`utm_` prefix, `ref` only, so `reference` and `ref_src` stay). The link is rebuilt from its own pieces without re-encoding, and sentence punctuation after a URL is kept. A tracking parameter on a line that is dropped anyway is not listed separately. `suppressed` keeps repeats (the same parameter on ten links appears ten times); the webhook handler decides how much of it to store.
- Normalization details: an `ignore_patterns` entry that is not a string, is blank, or matches the empty string (such as `x*`) is skipped like an invalid regex, because it would match every line and wipe the page.
- Normalization tests load fixtures with `import.meta.glob(..., { query: "?raw" })` because the Workers pool has no filesystem; `tests/env.d.ts` references `vite/client` for the types. A test checks that every rule has both a suppressed and a near-miss fixture.
- Structured diff details: a heading is `#` to `######`, a space, then text, and is always a block of its own (its `section` is its own text without any closing sequence, so `## Pro ##` is section `Pro` while `# C#` keeps its `#`; the block's `text` is the raw line), so a heading with no blank line next to it still splits the block. Fenced code is not special-cased, so a `# comment` inside a code fence reads as a heading.
- Structured diff details: blocks are matched by text alone, not by text plus section. A renamed heading therefore shows as one removed and one added heading (their sections differ, so they never pair) and the unchanged blocks under it stay out of the diff. A block moved under another heading is not reported unless the headings around it change.
- Structured diff details: inside a removed run followed by an added run (nothing unchanged between them), each removed block in order scans the added blocks in the same section that come after the one the previous pair took, takes the first one whose Dice score is at least 0.9 (R45, so a lightly revised block costs one comparison, not one per candidate) or else the highest-scoring one at 0.5 or more (the earliest wins a tie), so a new tier inserted before a price edit does not push the edit out of line. Pairs never cross. A pair with identical text counts as unchanged and is dropped. Runs longer than 50 blocks on either side pair position by position instead. This applies to a region the exact alignment gave up on too: it is paired best-match when each side has at most 50 blocks, and position by position only above 50. The score uses the set of lowercased character bigrams of the first 4096 characters of the block, newlines included; a block under two characters has no bigrams and never pairs.
- Structured diff cost (R42): the first computation of a diff is never cached if it is killed by the 10 ms CPU limit, so the cost has to be bounded inside `structuredDiff`, not by Task 9's cache. Four bounds: (1) blocks both versions start and end with are skipped, then `diffArrays` runs on block text with `maxEditLength: 80` (added plus removed blocks); past that it returns nothing and the whole remaining region is treated as one removed run and one added run, paired like any run (best match when each side has at most 50 blocks, position by position above 50; in the positional case edits that line up are still found and blocks that shifted show as removed and added); (2) Dice looks at most at the first 4096 characters of a block; (3) best-match pairing only runs on runs of at most 50 blocks per side; (4) all bigram work in one call (characters scanned to build a set plus the smaller set's size per comparison) is capped at 60,000. A revised block accepted on its first candidate costs about 2.5 times its length, so the budget reaches about 24,000 characters of revised text per version: every revised block of a page whose revisions total that much (for example 70 paragraphs of 300 characters), and the first ones in document order beyond it (about 13 paragraphs of 2,000 characters). The first time a comparison cannot be afforded the budget is spent for good (R45): the best candidate found so far for the block being scanned is discarded, because the candidates after that point were never scored, and nothing else is scored for the rest of the call, so those blocks stay removed and added; identical blocks still match, at no cost. Measured in Node on 100 KB, 1000 blocks: a few edits 1 to 2 ms warm; 40 edited blocks about 2.5 ms warm; every block rewritten about 4 to 7 ms warm and 8 to 13 ms on the first call of a fresh process. The bail itself takes 0.4 to 1.9 ms warm and about 3.2 ms on a first call, most of that one-time JIT cost. Before these bounds a full rewrite cost 100 to 200 ms.
- Facts diff details: a name that repeats on one side pairs by occurrence (first with first, second with second) instead of leaving later duplicates unmatched, so an unchanged list with two "Fee" entries diffs empty; surplus duplicates are added or removed. `changed` is in the new list's order and uses the new list's spelling of the name; field values compare with `!==` (no trimming).
- TinyFish client (`src/tinyfish/client.ts`): every call sends `X-API-Key` and `Content-Type: application/json` merged over the caller's headers. A non-2xx becomes `TinyFishError { status, code, message }`; `code` is `body.error.code`, else `body.code`, else `http_<status>`, and `message` is built from the response body only (the body's message or the first 300 characters of the text), so the key and the request headers can never reach an error. Spend is recorded after a 2xx only.
- `fetchPage` (`src/tinyfish/fetch.ts`): a per-URL entry in `errors[]` wins over `results[]` and is returned as `{ok: false, error}`; no entry and no result is `no_result`; an HTTP failure is `{ok: false, error: err.code, status}`. A result with an empty string for text is returned as `ok: true` with empty text; the callers decide what that means.
- `createMonitor` (R11 plus "no orphan monitors"): if the 201 arrives but the baseline has no text (no result, empty text or a non-empty `run.errors`), the new Monitor is deleted (best effort, a failed delete is swallowed) and a `TinyFishError` with code `baseline_failed` and status 502 is thrown, so a Monitor with no page row never eats one of the 24 slots. Known small over-count: the `monitor_check` spend row is written by `client.ts` on the 201 before the baseline is inspected, so a `baseline_failed` leaves a $0.005 row although TinyFish does not bill failed checks. Kept so spend is recorded in exactly one place.
- `deleteMonitor` treats a 404 as already deleted and returns normally (the cron's expiry step relies on that); any other failure throws. `listMonitors` reads `{monitors: [...]}` as the spike did (a bare array is accepted too) and does one unpaged GET; the spike only ever saw an empty list, so whether TinyFish pages a list of more than a page is unverified. `updateMonitor` uses `"name" in p` style checks, so `webhookUrl: null` sends `webhook_url: null` and an absent property is not sent.
- Agent rate limit (R34): `startFactsRun` waits 60 s (`opts.sleep`, real `setTimeout` by default) and retries up to 3 times on a 429 or a `RATE_LIMIT_EXCEEDED` code; after the last retry it throws a `TinyFishError` with code `RATE_LIMIT_EXCEEDED` (a bare 429 body has no code of its own, so the code is set on exhaustion). Other errors are not retried. A 200 without a `run_id` throws `no_run_id`. `getRun` returns `{status, result, num_of_steps}` exported as `AgentRun`, with `status` `UNKNOWN` and `num_of_steps` null when TinyFish leaves them out. `parseFacts` returns `[]` for an empty `items` array (the page had no facts) and null for anything malformed.
- TinySearch (R14, checked with one live GET): the response is `{query, results: [{position, site_name, snippet, title, url, date?}], total_results, page}` and `results` has up to 10 entries. `discoverFinePrint` runs its four queries in parallel, dedupes by exact URL in query order (first query wins the `kind`), and uses an empty title when a result has none. It only ever returns `pricing`, `policy` and `fees`; `other` exists in the type but nothing produces it. Query strings are encoded by `URLSearchParams`, so spaces are `+`.
- Browser (`src/tinyfish/browser.ts`): a port of the spike with the same CDP sequence, 6 s settle and clip. Additions: each command's 45 s timer is cleared when its reply arrives, a socket `close` or `error` rejects the commands still waiting (so `Browser.close` after the browser has gone does not wait 45 s), and the layout height falls back `cssContentSize` then `contentSize` then 800 as the Node spike did. `Page.navigate`'s `errorText` is not checked, as in the spike.
- Live browser test: `FINEPRINT_LIVE=1` makes `vitest.config.ts` read the key (`.dev.vars` first, see D6) and bind it as `LIVE_TINYFISH_API_KEY`; without it the binding does not exist and the test is skipped. `TINYFISH_API_KEY` stays `test-tinyfish-key` in every run. `vitest.config.ts` runs in Node but the project has no `@types/node`, so it types `process` locally and reads the file with `process.getBuiltinModule("node:fs")`. The default reporter hides `console.log` output from tests in this pool; use `--reporter=verbose` to see the bytes and height line.
- Task 4 has 25 tests in `tests/tinyfish.test.ts`, not the 7 first planned: they cover the client, each client file, the R34 retry cases, both `createMonitor` failure paths and the CDP error paths. The CDP sequence itself is proven only by the live test; Task 8 mocks `screenshotFullPage`.
- Repositories (`src/db/*`): row types keep the schema's snake_case names, and the 1/0 boolean columns are typed `number`, so a row read from D1 is the object. `insertVersion` takes a `NewVersion` (the eight core fields required; the seven capture fields optional and defaulting to NULL, `pending` and 0 attempts), so a caller can pass a full `VersionRow` or just the core. `insertPage` stamps `created_at` and throws on a duplicate url; callers check `getPageByUrl` first.
- Repositories: ordering. `listVersions` is newest first (the baseline is last), like `listChanges`; `listPages` is by `created_at` then insertion order; every "latest" query breaks a timestamp tie by `rowid`. `listPages.version_count` counts the baseline too. `listChanges` clamps its limit to 0 or more (a negative number would otherwise be SQLite's "no limit"); the cap on a public caller's `limit` is Task 9's. `since` is inclusive in `listChanges`.
- Repositories: `insertRun` reports `duplicate` only for a clash on `monitor_run_id` (`ON CONFLICT(monitor_run_id) DO NOTHING`, `meta.changes === 0`); a clash on `id` still throws. `markNoise` always sets `noise_suppressed = 1`, so a run that should carry `noise_reason "fetch_error"` without being counted as suppressed (see the change gate note above) needs its own small update in Task 7. `putCachedDiff` replaces the cached json when the pair already exists, so two requests racing to cache the same diff both succeed. `updatePage` and `updateCapture` write only a fixed list of columns and ignore any other key; an `undefined` value is skipped and `null` sets NULL.
- Repositories: `pendingCaptures` returns `pending` and `partial` versions only (R24, R46), so a version waiting for its Agent callback (`awaiting_facts`) never has attempts burned by the hourly repair. `captured_at <= olderThanIso` is inclusive.
- Task 5 has 20 tests in `tests/db.test.ts`, not the 5 first planned: those five plus the `awaiting_facts` exclusion (R24), the whitelist and bind checks of `updatePage` and `updateCapture`, `listPages` figures, the getters, the diff cache and the UTC day rollover of the public counter. `versionAsOf` returns `no_versions` for an unknown page id as well, so Task 9 checks that the page exists before it uses that answer.
